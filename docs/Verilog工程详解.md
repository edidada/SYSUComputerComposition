# Verilog 工程逐一讲解

这一篇把仓库里 7 个 Verilog 工程挨个讲明白，面向没看过代码、也暂时看不懂代码的人。每个工程都按同一套框架来说：**它想干嘛 → 内部怎么搭 → 你按什么、看什么 → 代码里一处有意思的细节**。

## 难度阶梯：从与门到 CPU

这 7 个工程不是并列的，而是一条逐级升级的路线：从验证一个与门开始，到能跑 MIPS 指令的 CPU，最后是专门的乘法器。

| 阶段 | 工程 | 难度 | 一句话 |
| --- | --- | --- | --- |
| 入门 | AndLogic | 最低 | 一个与门，30 行代码 |
| 基础 | ButtonCounter | 低 | 按键加一，数码管显示，学会多个模块拼接 |
| 基础 | FluentLight | 低 | 跑马灯，可调速、换向、暂停 |
| 运算 | FourDigitPlus | 中 | 4 位加法器，带进位/溢出标志 |
| CPU | SingleCPU | 高 | 单周期 MIPS CPU，一个周期干完一条指令 |
| CPU | MultiCPU | 高 | 多周期 MIPS CPU，5 个状态分步完成 |
| 运算 | Multiplier | 中高 | 8×8 移位相加乘法器 |

## 1. AndLogic —— 一个与门（最小起点）

### 它想干嘛

验证"两个开关同时为 1，灯才亮"。整个工程只有 1 个 `.v` 文件、30 行有效代码，是最小的入门实验（2023/09/12，全仓库最早的代码）。

### 内部怎么搭

没有任何子模块。`CLK` 的上升沿到来时，执行 `Result <= Data1 && Data2`。

### 你按什么、看什么

`Data1`、`Data2` 是两个拨码开关，`Result` 接一盏 LED。两个开关都拨上去，灯亮；否则灭。

### 一处细节

这里用了 `output reg` + `always@(posedge CLK)`，也就是**时序逻辑**——结果要等下一个时钟沿才更新。其实与门本来是纯组合逻辑，直接 `assign Result = Data1 && Data2` 就行。作者刻意写成时序版，是为了练"时钟沿触发"这个最基础的概念。

## 2. ButtonCounter —— 按键计数 + 数码管显示

### 它想干嘛

每按一次按键，数字加 1，并在七段数码管上显示出来。这是"多个模块拼起来"的第一个练习（6 个 `.v`）。

### 内部怎么搭

顶层 `ButtonCounter.v` 本身就是一张接线图，把 4 个零件连起来：

- `CLK_div`：分频器，把开发板几十 MHz 的高速时钟降到人眼能看见的速度
- `CLK_div2`：另一个分频器，速度不同，专供计数器
- `ButtonDebounce`：**按键消抖**
- `Counter`：计数器，看到按键信号为 1 就 `counter <= counter + 1`
- `Display`：把 16 位数字翻译成数码管的段选/位选信号

### 你按什么、看什么

按一下按键，数码管数字 +1；快速连按时不会乱跳（消抖的功劳）。

### 一处细节：消抖是怎么做到的

这是最经典的一段技巧：

```verilog
Button[0] <= Button_in;
Button[1] <= Button[0];
Button[2] <= Button[1];
assign Button_out = (Button[2]&Button[1]&Button[0]) | (~Button[2]&Button[1]&Button[0]);
```

三级触发器把按键信号像排队一样存了三拍，只有**连续三拍都稳定为 1**，或者**前两拍为 1、第三拍刚变 0**时才认账。机械按键按下时会"哆嗦"几毫秒，这个电路把抖动过滤掉了。

## 3. FluentLight —— 流水灯（可变速、可调向、可暂停）

### 它想干嘛

16 盏灯依次点亮，像跑马灯一样；能调速度、换方向、暂停、复位（5 个 `.v`）。这是**第四次实验**，也是课程里第一个真正有意思的交互设计。

### 内部怎么搭

顶层把三个零件串起来：

- `CLK_Div`：分频器，参数 `N = 12500000`。板子时钟 100MHz，数到 1250 万大约 0.125 秒翻转一次；`Sp` 开关可选 1/2/3/4 倍，于是有四档速度
- `Direct`：方向控制器，把 3 个物理开关翻译成 2 位"方向码"
- `Display`：灯位译码器，把一个 0~15 的数字变成 16 位中某一位亮

### 你按什么、看什么

- `speed`（2 位）：调快慢
- `RLSwitch`：往左跑还是往右跑
- `PauseSwitch`：暂停
- `Button_mid`：复位

### 一处细节：两位方向码藏了四种状态

| Dir | 含义 |
| --- | --- |
| `00` | 保持不动（暂停） |
| `01` | 复位到最左 |
| `10` | 向左递减 |
| `11` | 向右递增 |

`Direct.v` 就是把物理开关编码成这 4 个值；`Display.v` 里的 `case` 再译码成 16 位灯形。作者还特意写了 `if (Num == 0) Num = 16;` 处理绕回——灯跑到头会回到起点，不会卡死。

## 4. FourDigitPlus —— 四位二进制加法器

### 它想干嘛

拨两个 4 位二进制数，算出和，用数码管显示，并给出**进位标志 CF** 和**溢出标志 OF**。这是**第三次实验**（5 个 `.v`）。

### 内部怎么搭

`Top.v` 把 4 个零件连起来：

- `ALU.v`：核心，做 4 位加法
- `CLK_div` + `Display`：数码管显示
- `Mux2`：二选一开关，决定数码管显示"输入的两个数"还是"结果"

### 你按什么、看什么

`Button_left` / `Button_right` 两个按键切换显示内容；拨动 `Data1`、`Data2` 两组开关看结果；LED 看 CF/OF。

### 一处细节：这不是普通的加法器

一般教科书教的是"行波进位"：一位算完把进位传给下一位，像多米诺骨牌，慢。而这份 `ALU.v` 用的是**先行进位（carry-lookahead）**：

```verilog
assign G1 = Data1[0]&Data2[0];   // G = 产生进位
assign P1 = Data1[0]^Data2[0];   // P = 传递进位
assign C2 = G2 | (P2 & (G1));
assign C3 = G3 | (P3 & (G2 | (P2 & (G1))));
```

每一位的进位用表达式**直接算出来**，不用等前一位。这是组成原理课的经典重点，作者在这里扎扎实实做了硬件实现。

## 5. SingleCPU —— 单周期 MIPS CPU（第五次实验，17 个 `.v`）

### 它想干嘛

在 FPGA 上造一台能真正跑 MIPS 指令的 CPU，支持加减逻辑、加载存储、分支跳转、停机。这是课程的重头戏。

### 内部怎么搭

把一条指令的执行拆成一条组合电路链（但**一个时钟周期干完全部**）：

1. `ProgramCounter` 给出指令地址
2. `InstructMem` 取出 32 位指令
3. `Control CU` 译码，发出一堆控制信号（该不该写寄存器、ALU 做什么运算、要不要访存）
4. `RegisterFile` 读寄存器堆
5. `SignExtend` 把 16 位立即数符号扩展到 32 位
6. `Mux` 选择 ALU 的第二操作数（立即数还是寄存器值）
7. `ALU` 计算
8. `DataMem` 访存
9. 各种 `Mux` 选择写回数据、下一条 PC（顺序/分支/跳转三选一）

顶层 `SingleCPU.v` 有 238 行，几乎全是模块实例化——就是一张用代码画的电路图。

### 你按什么、看什么

`Start` 启动；`Stop` / `Verify` 配合 `IOPort` 从外部读写内存（`AddfromExtern` / `NumfromExtern` 输入地址和数据，`NumtoExtern` 输出结果）；`Halt` 指示停机。

### 一处必须说明的问题：目前编译不过

第 111 行实例化了一个叫 `CU` 的模块，连了 `ALUControl`、`RegRead1` 等十几个端口，但仓库里唯一的控制器 `Control.v` 定义的模块叫 `Control`，只有 `Instruct` 和 `MicroInstruct` 两个端口。

顶层 `SingleCPU.v` 用的控制信号是"一位一位拆开"的接口；而现存 `Control.v` 输出的是一个 32 位的 `MicroInstruct` 微指令字。两者对不上。这很可能是作者中途重构控制器但没同步改顶层，或者这份源码本身就没最终调通。

这不是 yml 或工具的问题，是设计代码本身的不一致。因此 CI 里把它设成了非阻断（警告注解），既不让整体绿灯变红，也保留问题供后续处理。

## 6. MultiCPU —— 多周期 MIPS CPU（第六次实验，12 个 `.v`）

### 它想干嘛

同样的 MIPS 指令集，但改成**多周期**——一条指令分成好几个时钟周期完成，每个周期干一件事。这是**第六次实验**，也是作者明确说"做到这个 + 乘法器就能拿到流水线分数"的关键成果。

### 内部怎么搭

和单周期最大的区别是多了两个零件：

- `Stage.v`：一个 5 状态的状态机，控制当前处于哪个阶段
- `PCWriter.v`：根据阶段和条件，决定下一条 PC 从哪来

硬件部件是**复用**的：同一个 ALU，在周期 2 算分支目标、周期 3 算运算结果。不像单周期那样每个功能都复制一份硬件。

### 5 个周期怎么走

`Stage.v` 里的编码很有意思，用独热码：

```text
10000 → 取指
01000 → 译码
00100 → 执行
00010 → 访存
00001 → 写回
```

而且它会**按需跳过**：`StageControl[2:0]` 由微指令的高 3 位给出，指示这条指令需要哪些阶段。比如纯算术指令不需要访存，状态机就从执行直接跳到写回。这个机制让简单指令跑得更快。

### 一处细节：微指令字怎么切

`Control.v` 输出 32 位的 `MicroInstruct`，不同的位段被切给不同部件用：

| 位段 | 用途 |
| --- | --- |
| `[31:29]` | 阶段控制（要经历哪些周期） |
| `[28:25]` | ALU 操作码 |
| `[24:20]` / `[19:15]` | 读寄存器编号 |
| `[14:10]` | 写寄存器编号 |
| `[8]` | 停机 Halt |
| `[5]`、`[3]`、`[4]` | 写回选择、读/写内存使能 |

这就是"控制字"的硬核实现——一条指令翻译成一个 32 位控制字，硬件按位取用。

好消息：这个工程用同一个控制器接口（顶层实例化 `Control CU (.Instruct(...), .MicroInstruct(...))`），和 `Control.v` 完全对得上，所以 iverilog 检查是通过的。作者重构控制器时把多周期版本同步好了，单周期那份遗留了。

## 7. Multiplier —— 8×8 移位相加乘法器（第七次实验）

### 它想干嘛

用拨码开关输入两个 8 位数，用硬件一步一步算出 16 位乘积，在数码管上显示。这是**第七次实验**，课程最后一个专项运算实验。

### 内部怎么搭

顶层 `Extern.v` 把 7 个模块连起来：

- `CLK_div` / `CLK_div2`：两种分频时钟
- `ButtonDebounce`：按键消抖
- `Switch`：按键翻转开关（按一次切到 0，再按切到 1）
- `Multiply`：**核心乘法器**
- `Display`：数码管显示

### 你按什么、看什么

`Switch[15:8]` 是被乘数、`Switch[7:0]` 是乘数；按一下按键切换显示"输入"还是"结果"；`Light` 两盏灯指示当前显示的是哪个。

### 一处细节：乘法是怎么"手算"出来的

`Multiply.v` 用一个 3 状态的状态机实现经典的**移位相加算法**：

```text
stage 00：准备 — result=0, temp=乘数, extend={0,被乘数}
stage 01：循环 8 次 —
    如果 temp 最低位是 1：result += extend
    temp 右移一位，extend 左移一位
stage 10：输出 result
```

这跟在纸上手算二进制乘法一模一样：看乘数当前位，是 1 就把被乘数（已左移到对应位置）加到结果里，然后整体右移。**每个周期算一位，8 个周期出结果**——用时间换硬件面积，非常典型且有效的设计。

这个工程里 `Extern.v` 有两处实例化曾缺少实例名（`Display(` 和 `Multiply(`），是纯语法笔误，已补上 `u_display` / `u_multiply`。现在 CI 检查能跑过。
